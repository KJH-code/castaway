# reflect — 작업 중간중간 레포 노트에 반영

> 이 레포(CASTAWAY)에서는: `docs/notes/` 에 계통별 노트(terrain · caves · perf · gameplay …)가 이미 정본으로 있다 — **계통에 속하는 결정 · 버그 원인 · 교훈은 그 계통 노트에**(CLAUDE.md '계통별 노트' 표), 계통 밖(작업 흐름 · 도구 · 여러 계통에 걸친 것)만 `decisions.md` · `bugs.md` · `lessons.md` 에. CLAUDE.md '규칙'에는 새로 생긴 '깨뜨리면 안 되는 것' · '같이 고칠 짝'만 한 줄로. 커밋 꼬리 줄은 이 세션 규칙대로 · 모델 이름 금지.

세션 끝에 몰아서 정리하지 않는다. 부를 때마다 그 사이 것만 반영한다.

## 1. 범위

- 이 세션에서 **마지막 reflect 이후** (이 세션에 reflect가 없었으면 세션 시작 이후)
- 이전 reflect에서 이미 쓴 것은 다시 쓰지 않는다

## 2. 추릴 것 — 이것만

- 결정과 그 이유
- 버그 원인 (증상이 아니라 원인)
- 실패한 접근과 왜 실패했는지
- 재사용 가능한 지식 (라이브러리 함정, 보안·성능 문제 포함)
- 이 세션에서 실제로 써먹은 노트 항목 (도움이 됐든, 틀려서 고쳤든)
- 오케스트레이터 모드를 썼으면 보고의 **"노트에 남길 것"** 섹션 (워커가 찾은 원인·실패·재사용 지식)
- 사용자 개인에 대한 것 (작업 습관, 선호하는 방식) — 레포가 아니라 auto memory로 (3번)

쓰지 않는 것: 코드 전체, 커밋 내용 복사, 단순 파일 수정, 패키지 설치 기록, 일시적 로그, 비밀값(토큰·비밀번호·키). 추릴 게 없으면 "반영할 것 없음"으로 끝낸다. 빈 노트를 만들지 않는다.

## 3. 위치

노트 폴더는 CLAUDE.md에 `notes: <경로>` 줄이 있으면 그 경로, 없으면 `docs/notes/`.

| 내용 | 위치 |
|---|---|
| 결정과 그 이유 | `decisions.md` |
| 버그 원인 | `bugs.md` (관련 파일·모듈 이름을 항목에 넣는다. start가 그 이름으로 찾는다) |
| 실패한 접근, 라이브러리 함정, 재사용 지식 | `lessons.md` |
| 써먹은 노트 항목 | 그 항목 끝에 `— 써먹음: <YYYY-MM-DD> <한 줄>` 추가. 내용이 틀렸으면 본문을 고치고 고쳤다고 적는다 |
| 정리한 `/memo` 메모 | 해당 파일로 옮기고 `inbox.md`에서 그 줄을 지운다 |
| 사용자 개인 습관·취향 | **레포에 쓰지 않는다.** auto memory가 켜져 있으면 거기 저장한다(Claude Code가 알려 준 auto memory 폴더의 MEMORY.md). 꺼져 있으면 저장하지 않고 그렇게 알린다 |

- 항목 형식: `## <짧은 제목>` 다음 줄부터 내용. 맨 끝에 태그
- 기존 항목과 같은 주제면 그 항목에 덧붙인다. 새 파일은 위 넷 말고는 만들지 않는다
- 폴더가 없으면 처음 쓸 때 만든다. 파일 맨 위에 한 줄 설명(`# 결정 — 무엇을 왜 정했나`)을 넣는다

## 4. 태그

모든 항목 끝에 하나:

- `[사용자 결정 · YYYY-MM-DD]` — 사용자가 정한 것
- `[실행 확인 · YYYY-MM-DD]` — 이 세션에서 명령을 실행해서 확인한 것
- `[AI 추정]` — 확인하지 않은 AI 판단

팀 레포면 누가 정했는지 남기면 좋다. 사용자가 이름을 알려 줬으면 `[<이름> 결정 · 날짜]`로 쓴다.

## 5. 확인 — 가볍게

넣을 목록을 `파일 → 추가할 항목(태그 포함)` 형태로 한 번에 보여준다.

- `[AI 추정]` 항목만 "맞음?"으로 묻는다. 틀렸다고 하면 빼거나 고친다
- 나머지(`[사용자 결정]`, `[실행 확인]`)는 묻지 않고 바로 쓴다
- auto memory로 갈 것은 따로 묶어서 "저장할까?"로 묻는다
- 매번 전체 반박 패스를 돌리지 않는다 (무거우면 안 부르게 된다)

## 6. 쓰기 + 커밋

- 노트 파일만 커밋한다. 작업 중인 다른 변경은 섞지 않는다:
  ```bash
  git add -- <바꾼 노트 파일들>
  git commit -m "notes: <요약>" -- <바꾼 노트 파일들>
  ```
- push는 하지 않는다. 노트는 지금 브랜치와 같이 PR로 올라가서 팀원이 리뷰한다
- 레포 규약상 커밋하면 안 되는 상황(예: 커밋 훅이 막음, 사용자가 커밋하지 말라고 함)이면 파일만 쓰고 그렇게 보고한다

보고: 바꾼 파일 목록 + 커밋 해시 한 줄(+ auto memory에 저장한 것 한 줄). 그리고 하던 작업으로 돌아간다.
