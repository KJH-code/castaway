# 워커 지시서 공통 양식

워커는 메인과 사용자가 나눈 대화를 하나도 모른다. 지시서에 없는 건 없는 것이다. 저노력 워커는 빈칸을 추측으로 채우지 않고, 채우더라도 틀리게 채운다. 그래서 아래 칸을 전부 채운다.

```
# 목표
한 문장. 이 일이 끝나면 무엇이 존재하는가.

# 맥락
- 프로젝트가 무엇인지 2~3줄
- 이 작업이 전체에서 어떤 조각인지
- 사용자가 인터뷰에서 정한 것 중 이 작업에 걸리는 것 (뉘앙스 포함: "여기는 대충", "여기는 남한테 보여줄 거라 깔끔하게")
- 이 레포: CLAUDE.md '규칙' · '같이 고칠 짝' 가운데 이 작업에 걸리는 줄과 그 계통 노트(`docs/notes/*.md`) 대목을 옮겨 적는다 — 워커는 노트를 저절로 안 읽는다

# 범위
- 건드려도 되는 파일·폴더
- 건드리면 안 되는 파일·폴더 (다른 워커 영역 포함)
- 기준 브랜치와 작업 브랜치 이름, 저장소 규약

# 입력
- 읽어야 할 파일, 데이터 위치, 참고할 기존 코드

# 완료 기준
- 확인 가능한 조건으로. "잘 동작" 금지.
  예: `npm test` 통과 / 서버 켜고 두 클라이언트 접속 시 넉백 적용 / 결과 CSV에 열 a,b,c
- 이 레포의 검사(CLAUDE.md '확인하는 법'): `node tools/check-syntax.mjs *.html beta/*.html engine/js/*.js presets/*.js` · 전역 이름 겹침(이어 붙여 `node --check`) ·
  `node tools/smoke.mjs`(파일 이름으로 좁혀도 된다) · 값은 `node tools/probe.mjs island_world.html --run 파일.js`(헤드리스는 실시간의 1/20 — 함수를 직접 부른다)

# 커밋
- 제 작업 트리에만 · 한국어로 무엇을 왜 · 끝에 아래 꼬리 줄(메인이 채운다) · 모델 이름 금지 · 푸시 · PR · 병합은 하지 않는다
  (꼬리 줄)

# 하지 말 것
- 범위 밖 리팩터링, 새 의존성 추가(필요하면 보고), 추측으로 스펙 바꾸기

# 막히면
- 스펙이 애매하거나 모순이면 추측해서 진행하지 말고 멈추고 질문을 보고에 적는다.

# 보고 형식
- 한 일 (파일별 1줄)
- 완료 기준 각각 충족 여부와 확인 방법
- 막힌 것 / 확신 없는 것
- 커밋 해시 또는 결과 파일 경로
```
