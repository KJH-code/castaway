- 생존 스탯 4종(체력·기력·허기·수분) + 손전등 배터리
- 4칸 핫바, 줍기/버리기/사용, 무게에 따른 이동속도 페널티
- 고철 판매대 + 할당량, 10분 낮→밤 사이클(어두워질수록 적 증가)
- 배회/추격 상태의 적 AI, 삽 근접 공격

**바로 손볼 만한 곳**
- `CFG` 객체 하나에 물리·속도·시간 값 전부 모아뒀습니다
- `ITEM_DEFS`에 아이템 추가하면 자동으로 인벤토리에 붙습니다
- 적이 아직 벽을 통과합니다 (`updateEnemies`에 `resolveCollision` 붙이면 해결)

**생성 파이프라인** — 노이즈만 쌓지 않고 실제 지형 형성 과정을 흉내냅니다.
1. 도메인 워핑한 방사 감쇠 → 만·반도가 있는 불규칙 해안선
2. fBm 구릉 + ridged 산릉 × 산맥 마스크, 해수면 ±15m 구간을 압축해 넓은 해빈 형성
3. 열적 침식(안식각) → 수적 침식(물방울 3.8만 개, 관성·용해능·퇴적) → V자곡과 선상지
4. D8 흐름 누적으로 하천 추출 및 하도 절개
5. 탁월풍 라인 스윕으로 지형성 강수와 비그늘 계산 (시드마다 풍향이 바뀜)
6. 표고·경사·습도·TWI(지형습윤지수)로 12개 바이옴 분류

**제작 트리와 연결되는 지질 배치** — 광종을 실제 산출 환경에만 놓았습니다.
- 부싯돌은 해빈 자갈과 하상에, 점토는 하천 범람원 저지에
- 공작석(구리)은 중고도 노출 암반, 석석(주석)은 하류 사광 — 청동을 만들려면 산과 강을 둘 다 돌아야 함
- 늪철광은 이탄지 한정. 습지가 없는 건조한 섬 시드에서는 철기가 막힙니다

10개 시드·파라미터 조합으로 검증했고 생성 시간은 200~400ms, 모든 시드에서 10개 자원이 다 나옵니다.

**동작 방식**
1. 1차는 기존대로 — 늪철광은 이탄지, 석석은 하류 하천에만
2. 하한 미달이면 각 광종의 연속 점수 함수로 육지 셀 전체를 줄 세워 위에서부터 보충. 습지가 없는 섬이라도 늪철광은 TWI(배수 불량 지수)·습도·완경사 점수가 가장 높은 곳, 즉 "그나마 가장 늪에 가까운 곳"에 놓입니다. 무작위 살포가 아니라서 위치가 여전히 납득 가능합니다
3. 광물을 나무보다 먼저 채웁니다. 좁은 섬에서 나무가 자리를 다 먹는 문제가 있었습니다
4. 간격을 2→1→0셀로 좁혀가며 재시도하고, 그래도 모자라면 겹쳐서라도 채웁니다

**하한은 섬 크기에 비례**해서 줄어들되 0이 되지는 않습니다. 큰 섬은 늪철광 24개, 극소 섬은 9개 — 어느 쪽이든 철기까지는 갈 수 있습니다.

**검증** — 무작위 파라미터 60회 스윕에서 자원 전무 0건. 육지가 3.5%만 남는 극단 설정(해수면 +14m)에서도 10종 전부 배치됩니다. 보장을 끄면 같은 조건에서 7종이 사라지므로 실제로 이 패스가 일하고 있는 게 맞습니다.

UI에 **자원 보장** 토글과 **하한 보정** 통계를 넣었고, 범례에서 각 자원의 실제 배치 수를 볼 수 있습니다. 주황색 `24⁺¹¹`처럼 표시된 건 자연 배치 24개에 보정 11개가 더해졌다는 뜻이라, 어느 시드가 어떤 자원에 인색한지 바로 확인됩니다.

- 하루 24분 주기로 태양 고도·광색·안개 밀도·하늘색이 8개 키프레임 사이를 보간합니다. 밤에는 손전등 없이는 거의 안 보입니다

**플레이어**
- 경사 45°를 넘는 사면은 오르지 못하고 축별로 미끄러집니다. 절벽이 실제 지형 장벽이 됩니다

- 발소리가 지면 재질별로 다릅니다 (모래 1500Hz, 암반 2600Hz, 습지 500Hz — 밴드패스 필터 하나로 처리)

그러니까 **문구만 단계처럼 보일 뿐, 실제 동작은 한 덩어리**입니다. 부싯깃을 화덕에 넣는 별도 조작도, 불씨를 옮기는 조작도, 부는 조작도 없습니다. 앞서 제가 "단계를 보여준다"고 한 게 오해를 만든 것 같습니다. 보이는 건 문구뿐입니다.

그리고 방향도 반대로 잡으셨습니다. **활비비는 부싯깃에 비비는 게 아닙니다.** 비비는 대상은 불씨판(hearth board)이고, 거기서 나온 톱밥이 눌어붙어 불씨가 됩니다. 부싯깃은 그 불씨를 받아내는 별도의 마른 풀뭉치입니다. 비비는 판과 받는 뭉치는 다른 물건이에요.

물으신 대로 진짜 공정을 조작으로 나누면 이렇게 됩니다.

1. 활비비 + 불씨판을 비빈다 → **불씨** 획득 (현재 불씨판이라는 물건이 아예 없습니다)
2. 불씨를 **부싯깃 뭉치**에 옮긴다
3. 뭉치를 들고 분다 → 불꽃
4. 타는 뭉치를 **화덕 땔감 밑에 넣는다**

E를 네 번 눌러야 하고, 중간에 시간 제한도 붙습니다. 불씨는 옮기지 않으면 꺼지고요.

다만 방금 "실패 없게 해달라"고 하신 방향과는 반대로 갑니다. 단계가 늘면 각 단계마다 놓칠 여지가 생기니까요. 어떻게 할까요?

1. **지금처럼 한 번에** — E 8초, 부싯깃 1개 소모 (실패 없음)
2. **공정대로 4단계** — 불씨판 아이템 추가, 조작 4번, 시간 제한 있음

Caps Lock은 원인이 아닙니다. 키 판정에 `e.code`를 쓰는데 이건 Caps Lock이나 한/영 상태와 무관하게 항상 `KeyW`로 들어옵니다.

진짜 원인은 **터치 감지 코드**였고, 제 실수입니다.

```js
const isTouch = ('ontouchstart' in window) || navigator.maxTouchPoints > 0;
```

터치스크린이 달린 노트북은 여기서 `true`가 됩니다. 그러면 마우스가 멀쩡히 있는데도 게임이 "모바일"로 판단하고 세 가지가 동시에 망가집니다.

1. **터치 UI가 화면 전체를 덮습니다.** `#touch`는 `inset:0` 전체 화면 div인데 z-index 5로 캔버스 위에 깔립니다. 마우스 클릭이 전부 여기에 먹혀서 캔버스에 닿지 않습니다
2. **포인터 잠금을 건너뜁니다.** `if(!isTouch) requestPointerLock()` 조건이라 시점 조작이 시작되지 않습니다
3. **키보드 입력이 매 프레임 지워집니다.** `applyTouch()`가 가상 스틱의 중립값(0)을 WASD에 그대로 써버려서, 키를 눌러도 다음 프레임에 false가 됩니다

**고친 내용**

- `isTouch`(터치 가능)와 `hasMouse`(마우스 있음)를 분리했습니다. `matchMedia('(pointer:fine)')`로 실제 포인터 종류를 봅니다. 터치 UI는 **마우스가 없을 때만** 표시됩니다
- 터치 오버레이에 `pointer-events:none`을 주고 스틱과 버튼에만 `auto`를 줬습니다. 혹시 표시되더라도 클릭을 삼키지 않습니다
- `applyTouch()`는 **스틱을 실제로 잡고 있을 때만** 키를 건드립니다. 놓는 순간 한 번만 해제합니다
- 포인터 잠금을 `click` → `pointerdown`으로 바꾸고 `pointerType === 'touch'`면 무시합니다
- 알트탭으로 창을 벗어나면 눌린 키가 남아 계속 걸어가던 문제도 함께 고쳤습니다 (`blur` 시 전체 해제)
